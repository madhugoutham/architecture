A–Z Vocabulary you'll see everywhere

EPP (Endpoint Picker)
The routing brain. A service the proxy consults per request; it answers “send this to pod X”. It never proxies the inference bytes itself.
ext-proc
Envoy's External Processing protocol — a gRPC side-channel that lets a proxy pause a request and ask an external service (EPP) what to do.
InferencePool
A Kubernetes CRD that declares “these pods serve this model, and this EPP picks among them”. Configuration, not a runtime hop.
KV cache
Per-token attention state (Key/Value tensors) the model keeps on GPU during generation. Reusing it for a repeated prompt prefix skips expensive prefill work.
Prefill / Decode
Prefill = process the whole prompt in one pass (compute-heavy). Decode = generate tokens one at a time (latency-sensitive). They can run on different pods.
Prefix cache hit
A new request whose prompt starts with bytes a pod has already processed — the pod can reuse its stored KV blocks instead of recomputing.
Filter / Scorer / Picker
EPP's three scheduling plugin types: filters eliminate ineligible pods, scorers rank survivors with weights, a picker chooses the winner.
Snapshot
The freshest metrics EPP holds in memory for one pod (queue depth, KV usage…). Scoring reads snapshots — it never makes live HTTP calls per request.
ZMQ KV events
Messages vLLM can publish (BlockStored / BlockRemoved / AllBlocksCleared) telling EPP how its KV cache changed. Optional, async, lossy.
Tier
Where a KV block physically lives: GPU, CPU RAM, filesystem, or object store. EPP can weight each tier differently when scoring prefix hits.
